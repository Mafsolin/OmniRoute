## Подтверждено (зелёные волны)

- Текст ответа не теряется и не дублируется во всех сценариях; частичный текст
  при обрывах сохраняется ровно один раз; tool-call аргументы не искажаются.
- Отмена клиентом (abort, c8) закрывает все upstream-слоты (8/8 disconnected,
  `finalUpstreamActive=0`), повторов нет.
- Апстрим получает ровно ожидаемый id модели (f2-префикс снят), а также
  неизменённые effort/max_tokens/temperature/system-инструкции.
- health-эндпоинты под генерацией отвечают 200 без столлов сколь угодно долго;
  стриминг-фаза `/healthz` на c4/slow: p95 ≈ 0.5s, отдельных столлов >8s нет.
  Фаза установки стримов (первые ~2s волны) на загруженном хосте давала пробам
  до ~1.5–2s (см. «Хост»).
- 429/500 не превращаются в «успех»: клиент видит либо HTTP-статус, либо
  терминальный in-stream error.

## Находки (pre-existing поведение — ветка эти пути не меняла)

Ветка `8bb49dd83..2990ad921` не трогала `open-sse/handlers/chatCore/**`,
`earlyStreamKeepalive.ts`, `sseHeartbeat.ts` (git log пуст), поэтому обе
находки ниже — не регрессии, а задокументированное поведение продукта.

1. [A] 429 при единственном аккаунте + lazy-retry: гейтвей отвечает клиенту
   200+keepalive и ретраит единственный synthetic-аккаунт (до 8 upstream-попыток
   с cooldown), терминальный сигнал не выходит за 30s клиентского дедлайна
   (c1: 1/1 deadline; c4: 4/4 deadline; c8: 7/8 upstream_error, 1/8 deadline).
   Продуктовый вопрос: клиентский потолок ретраев / более ранняя нотификация
   (пробник использует строгий 30s дедлайн).
2. [B] Mid-stream обрыв/ошибка апстрима (early-EOF без `[DONE]`, error-фрейм)
   финализируется к клиенту как чистый `[DONE]` (`outcome=completed`,
   26/26 в калиброванном прогоне) — явного сигнала обрыва нет.
   Продуктовый вопрос: surface-ить ли обрыв (stream_truncated / error-фрейм).

## Калибровка харнесса по итогам первого живого прогона

- `model:"keepalive"`-фреймы (open-sse/utils/earlyStreamKeepalive.ts, фича от
  2026-07-28, есть и в старом проде) — протокольный heartbeat, не вывод модели:
  теперь считаются отдельно (`keepalives`), не попадают в model identity.
- Таймаут health-проб 2s→8s: измеряем реальную длительность столлов, а не
  обрезаем на 2s.
- Overlap-эвиденс требуется только для волн длиннее семплинга; для ретрай-волн
  (500) принимается «отвечали 200 при inFlight>0».
- Ожидания 429/500 приведены к дизайну ретраев: поверхность = HTTP-статус или
  терминальный error-фрейм; «deadline без терминала» остаётся фейлом.
- Суммарно фейлов после калибровки: **38** (класс A — 12, класс B — 26);
  до калибровки было 139 (из них ~50 — артефакты харнесса, остальное — те же A/B).
